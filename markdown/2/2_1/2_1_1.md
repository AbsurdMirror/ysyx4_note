### 为什么printf()的输出要换行?

不使用换行会导致输出内容的可读性极差，难以分析输出内容是由哪条 `printf` 语句输出的。

网络搜索得知：[Linux下printf函数不加\n就不能输出相关的内容](https://blog.csdn.net/qq_37284607/article/details/112470262)

unix上标准输入输出都是带有缓存的，一般是行缓存。对于标准输出，需要输出的数据并不是直接输出到终端上，而是首先缓存到某个地方，当遇到行刷新标志或者该缓存已满的情况下，才会把缓存的数据显示到终端设备上。

对以上内容进行测试：

- 测试代码: [完整c文件](./2_1_1_test_printf.c)

  ```C
    // with '\n'
    printf("test with \\n \n");
    sleep(1);
    printf("printf \n");

    sleep(1);

    // without '\n'
    printf("test without \\n");
    sleep(1);
    printf("printf");
  ```

- 测试结果
  - 在windows下: 加不加换行均在 `printf` 执行后直接输出内容。
  - 在linux下: 加换行时在 `printf` 执行后直接输出内容；不加换行时在第二句 `printf` 执行后才输出全部内容。

### 实现算术表达式的递归求值

此部分需要实现的内容较多，罗列几个重点：

- 错误处理：函数返回结果的同时还要返回执行情况，解决方法是使用了结构体，函数返回一个结构体，包括结果值和执行情况两个属性。另一种解决方法是输入参数添加一个指针，把执行情况写入指针指向的内存中，函数返回结果值。

- 无符号运算：计算结果为无符号数，但是计算过程中可能出现负数（如 2-3），因此计算过程中使用 `int` 类型存储中间变量，最后返回 `uint32_t` 类型。

- 括号检测：采用的方法是扫描一遍tokens，用一个整数记录遇到的括号，例如从左向右扫描，遇到左括号加1，遇到右括号减1，扫描过程中出现负值或结果不为0均说明括号格式有误。

**标注** : *词法分析和语法分析可能有更好的方法，后续抽时间学习编译原理，可能找到答案。*

## 如何测试你的代码

### 表达式生成器如何获得C程序的打印结果?

1. 使用 `fopen` `fputs` 将C代码写入文件
2. 使用 `popen` 或 `system` 编译C文件
3. 使用 `popen` 运行C文件。注意 `popen` 会返回一个指向标准输出流的文件指针，而 `system` 无法获得
4. 使用 `fscanf` 或 `fread` 等函数读取 `popen` 标准输出流。使用 `fscanf` 的好处是可以将输出内容直接读为整数类型

### 除0的确切行为

- 编译过程中会有 `warning` 出现，提示存在除0行为
- 运行过程中会有 `Floating point exception` 出现，即浮点数例外

### 过滤除0行为的表达式

在编译和运行都可识别到除0行为，为了尽早识别除0行为，选择在编译过程进行过滤除0行为。具体方法如下：

- 为了获取命令执行输出，将编译使用的 `system` 函数改为 `popen`
- 为了获取标准错误输出，在命令最后添加 `2>&1`，即将标准错误输出添加到标准输入中。
- 读取标准输出到字符数组中，并使用 `strpbrk` 进行字符串搜索，如果找到 `warning` 或 `error` ，就停止本次表达式生成，重新生成。

**标注** : *这种方法同时能检测到整数溢出的情况*
