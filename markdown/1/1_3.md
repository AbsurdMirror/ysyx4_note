## 尝试理解计算机如何计算

我们在写高级语言代码（如C、Python）时，只需要写一行 `for` 、 `while` 之类的代码，就可以将重复性的工作省略掉，但是计算机在运行这些代码时，需要不停地重复循环中的内容，直到循环结束。

另外，计算机的寄存器资源有效，我们可以在高级语言代码中定义千千万万个变量。但是计算机运行时，它不可能把这些变量全部加载到寄存器中，只能把附近的指令需要的变量读入寄存器，其他的变量存放在内存中，因此C语言的一句 `a = b + c` ，在计算机运行时需要先把变量 `b` 、`c` 读取到寄存器中，并准备一个存放结果的寄存器，然后才能执行加法，最后把结果寄存器写入到 内存中存放 `a` 的位置中。

## kconfig生成的宏与条件编译

```C++
// macro concatenation
#define concat_temp(x, y) x ## y
#define concat(x, y) concat_temp(x, y)
#define concat3(x, y, z) concat(concat(x, y), z)
#define concat4(x, y, z, w) concat3(concat(x, y), z, w)
#define concat5(x, y, z, v, w) concat4(concat(x, y), z, v, w)

// macro testing
// See https://stackoverflow.com/questions/26099745/test-if-preprocessor-symbol-is-defined-inside-macro
#define CHOOSE2nd(a, b, ...) b
#define MUX_WITH_COMMA(contain_comma, a, b) CHOOSE2nd(contain_comma a, b)
#define MUX_MACRO_PROPERTY(p, macro, a, b) MUX_WITH_COMMA(concat(p, macro), a, b)
// define placeholders for some property
#define __P_DEF_0  X,
#define __P_DEF_1  X,
#define __P_ONE_1  X,
#define __P_ZERO_0 X,
// define some selection functions based on the properties of BOOLEAN macro
#define MUXDEF(macro, X, Y)  MUX_MACRO_PROPERTY(__P_DEF_, macro, X, Y)
#define MUXNDEF(macro, X, Y) MUX_MACRO_PROPERTY(__P_DEF_, macro, Y, X)
#define MUXONE(macro, X, Y)  MUX_MACRO_PROPERTY(__P_ONE_, macro, X, Y)
#define MUXZERO(macro, X, Y) MUX_MACRO_PROPERTY(__P_ZERO_,macro, X, Y)
```

相关代码如上所示，执行函数 `MUXDEF(CONFIG_TRACE, "ON", "OFF")` ，分析如下：

- [1] 定义 `CONFIG_TRACE` 为1，即在 `nemu/include/generated/autoconf.h` 中 `#define CONFIG_TRACE 1`，下面进行预处理。
  1. `MUXDEF(CONFIG_TRACE, "ON", "OFF")`
  2. 对 `CONFIG_TRACE` 进行宏替换：`MUXDEF(1, "ON", "OFF")`
  3. 对 `MUXDEF` 进行宏替换：`MUX_MACRO_PROPERTY(__P_DEF_, 1, "ON", "OFF")`
  4. 对 `MUX_MACRO_PROPERTY` 进行宏替换：`MUX_WITH_COMMA(concat(__P_DEF_, 1), "ON", "OFF")`
  5. 对 `concat` 进行宏替换：`MUX_WITH_COMMA(concat_temp(__P_DEF_, 1), "ON", "OFF")`
  6. 对 `concat_temp` 进行宏替换：`MUX_WITH_COMMA(__P_DEF_1, "ON", "OFF")`
  7. 对 `MUX_WITH_COMMA` 进行宏替换：`CHOOSE2nd(__P_DEF_1 "ON", "OFF")`
  8. 对 `__P_DEF_1` 进行宏替换：`CHOOSE2nd(X, "ON", "OFF")`
  9. 对 `CHOOSE2nd` 进行宏替换：`"ON"`

- [2] 定义 `CONFIG_TRACE` 为0，即在 `nemu/include/generated/autoconf.h` 中 `#define CONFIG_TRACE 0`，预处理与上述过程相同。

- [3] 不定义 `CONFIG_TRACE` ，即在 `nemu/include/generated/autoconf.h` 中无 `#define CONFIG_TRACE`，下面进行预处理。
  1. `MUXDEF(CONFIG_TRACE, "ON", "OFF")`
  2. 对 `MUXDEF` 进行宏替换：`MUX_MACRO_PROPERTY(__P_DEF_, CONFIG_TRACE, "ON", "OFF")`
  3. 对 `MUX_MACRO_PROPERTY` 进行宏替换：`MUX_WITH_COMMA(concat(__P_DEF_, CONFIG_TRACE), "ON", "OFF")`
  4. 对 `concat` 进行宏替换：`MUX_WITH_COMMA(concat_temp(__P_DEF_, CONFIG_TRACE), "ON", "OFF")`
  5. 对 `concat_temp` 进行宏替换：`MUX_WITH_COMMA(__P_DEF_CONFIG_TRACE, "ON", "OFF")`
  6. 对 `MUX_WITH_COMMA` 进行宏替换：`CHOOSE2nd(__P_DEF_CONFIG_TRACE "ON", "OFF")`
  7. 对 `CHOOSE2nd` 进行宏替换：`"OFF"`

## 究竟要执行多久?

函数 `cpu_exec()` 的输入参数类型为 `uint64_t`，是无符号的数，当输入为-1时实际值为该类型的最大值，使用printf函数可以验证，其值为1844674407370955161。

## 谁来指示程序的结束?

- 如果程序直接运行在cpu上，无操作系统，程序通常最终停在一个死循环中；
- 如果程序运行在操作系统上，在main函数运行结束后，会向操作系统发送一个标志，由操作系统结束进程。此方面未深入研究。

## 优美地退出

- 该错误信息不只在运行NEMU之后直接键入q的情况下触发，只要在客户程序未运行结束时使用q命令退出均会触发。
- 触发原因是客户程序未运行结束时 `nemu_state` 一直为 `Running`，`cmd_q` 直接退出 `sdb_mainloop` 函数，接着会执行 `is_exit_status_bad` 函数，由于`nemu_state` 为 `Running`，判断为错误的退出状态，输出错误信息。
- 解决方法：在退出 `sdb_mainloop` 函数之前将 `nemu_state` 为 `End`。
